# CLAUDE.md

Guidance for Claude Code working in this repo. Kept intentionally lean — current-state facts and non-obvious gotchas, not a changelog. Git history has the story if you need it.

## Commands

- `flutter pub get` / `flutter run` / `flutter analyze` (no custom lint rules).
- `flutter test` — the one test file is unmodified stock boilerplate referencing a nonexistent `MyApp`; it fails as-is and isn't a real signal.
- `flutter build apk` / `appbundle` / `ios` — release builds. Flutter SDK lives outside PATH at `/c/flutter/flutter/bin/flutter.bat`.
- **Gradle builds fail from this Bash tool** (`Unable to establish loopback connection`, a sandbox networking restriction) — `flutter build apk`/`appbundle` must be run by the user in their own PowerShell. `flutter analyze`/`pub get`/`test` work fine here. If a real terminal build fails with `Unsupported class file major version 70`, that's a JDK mismatch — fix with `flutter config --jdk-dir="C:\androidstudio\jbr"`.
- iOS builds only happen on the Mac (Xcode/CocoaPods). See `IOS_RELEASE_GUIDE.md` for the full build/archive/submit checklist.

## Architecture

**Startup (`main.dart`)**: `SentryFlutter.init` wraps the whole startup sequence, not just `runApp`. DSN is a write-only client id, safe to commit. A long list of singletons `.init()` sequentially before `runApp`; only `CollectionProvider`/`WishlistService`/`CommunityService` are in the `MultiProvider` — everything else is a plain `ChangeNotifier` singleton accessed via `.instance`, not `context.watch`. `ThemeService` drives `MaterialApp.theme` via a top-level `ListenableBuilder`, bypassing Provider. `kWishlistEnabled`/`kCommunityEnabled` gate those tabs entirely.

**Device identity** (`device_identity.dart`): random UUID per install, persisted, used for barcode-consensus voting (`UNIQUE(barcode, user_id)`) and Community submit cooldowns. Must `init()` before either feature is touched.

**Pixel avatar system** (`data/pixel_cosmetics.dart`, `widgets/pixel_avatar_widget.dart`): ~100-entry catalog (`assets/avatar_pixel/`), replaced an older photo-crop figure system. `background_cosmetics.dart` is backgrounds-only now (52 entries) — different catalog, `AvatarState.backgroundId` still resolves through it. Compositing uses anchor-pixel zones, not per-item scale correction: head 28 / torso 32 / legs 36 (of 96 units), `BoxFit.fill` on head/torso/legs so seams touch exactly, hat is the exception (`BoxFit.contain` + 7-unit dip anchor, since hats are drawn at an angle). Z-order: legs → torso → head → hat. `AvatarWidget` is the shared render adapter every screen uses. `itemId` (equippable) has no ground-accessory rendering anywhere — `groundAccessoryOf()` always returns `null` post-cutover, a known unclosed gap.

**Secret cosmetics**: `isSecret` marks a hidden item on either catalog (currently one: `px_item_secretxwing`, 8-frame). `SecretItemCodes.byCode` maps codes to ids; checks both catalogs.

**Reward pool**: `LootService.unlockOrDupePayout()` is the one shared grant helper behind every path that can hand out a possibly-already-owned id (daily claim, bonus rolls, bundles, hidden themes, What's New). `_rewardPool` draws from both catalogs, excludes `isSecret` and anything already claimed by an achievement/bundle/hidden-theme/starter set.

**Daily Five** (`daily_five_service.dart`): `DailyTask` enum persists as a `Set<int>` of `.index` — renaming a value must happen in-place, never reorder/remove, or it silently corrupts everyone's "done today" state. Local reminder notification (60% chance, 4–8pm window) pays +10 Briks only on days it actually fires (order-of-checks fixed so a late app-open after the window passes can't grant it for a no-show notification). `LootService.streak.canClaim` self-corrects against the current date on every read now, not just at cold start.

**Backgrounds / Den** (`backgrounds_art.dart`, `den_scene.dart`, `brick_den.dart`): `bgPalettes` = colors, `bgImageIds`/`denImageAsset()` = which of the 52 backgrounds have real photo art (48 do; `bg_workbench`/`bg_snowfield`/`bg_maproom`/`bg_shadowrealm` are still procedural-only). `den_scene.dart`'s `DenSceneContent` is the actual scene; `brick_den.dart` is just screen chrome. `hasImage` skips all procedural wall/floor/decor and every placeholder ("locked" plaques, showcase boxes) once real art exists. The separate pixel-art HUD overlay (badges/trophy shelf/diamond) was **removed entirely 2026-08-25** — read as a sticker pasted over the scene no matter how it was styled; `den_hud.dart`/`assets/den_hud/` are now dead code, left on disk. The text/emoji trophy list below the scene is unaffected and is the only surviving display of that info.

**Collection model** (`lego_set.dart`): `LegoSet.num` is always stored without the `-1` suffix — normalize any new input path with the same regex or dedup silently breaks. `subtheme` is dead for Rebrickable-sourced sets (the API never actually populates it); every consumer already OR-checks `theme` too. Sealed/open are fully parallel data (`ebaySealed`/`ebayOpen` etc.); `ebayAvgIsFallback` flags a price borrowed from the other condition.

**External APIs** (`services/api.dart`): Rebrickable and BrickSet are called directly from the app with embedded keys (both low-sensitivity/public-tier). eBay goes through the Worker (`K.workerUrl`) with a 7-day D1 cache server-side and an independent 3/week client-side throttle. `FeatureFlagService` fetches `/features` once at launch, fails safe to all-off on any error. Live flags: `FEATURE_COMMUNITY_FEED`/`FEATURE_SCANNER` (on), `push_notifications` (off by default, added 2026-08-26). The Worker's source lives in `cloudflare-worker/` (`wrangler.toml` + `worker.js`, the actual deployed bundle) — direct `wrangler deploy` from there is the normal workflow now. **`git push` and `wrangler deploy`/`wrangler pages deploy` are separate, unlinked actions** — a commit landing doesn't mean the live Worker/Pages site reflects it; always verify live content after a change that needs deploying, not just that the commit succeeded.

**Barcode seeding** (`runSeedBatch`/`discoverNewSets` in `worker.js`): walks Rebrickable's set list, cross-checks each against `barcode_cache`, and calls BrickSet's `getSets` for anything missing. `BRICKSET_SEED_DAILY_BUDGET=500` is an empirical guess, not a confirmed quota. Cron: hourly + 6-hourly (Workers Free's 5-cron-per-account ceiling forced consolidation). This pipeline's own BrickSet usage tracking has zero visibility into the app's direct client-side BrickSet calls, which share the same real quota — unclosed gap. As of 2026-08-27: once the one-time full-catalog backfill finishes, discovery **stops re-walking forever** (permanent `rb_backfill_complete` flag) — ongoing new-release discovery is left to the separate, cheaper `runMonthlyCatchup` (first 4 pages, early each month) instead of re-scanning everything on a loop.

**Website** (`cloudflare-site/`): `index`/`checker`/`parts-merger`/`privacy`/`terms` share one design-token system lifted from `app_theme.dart`'s `BT` class, same manual dark/light toggle. `quest-admin.html` is the live Quest Admin authoring tool (see What's New below). `partchecker.pages.dev` is retired, redirect-only now.

**Parts Merger**: `POST /parts-merge` sums parts across up to 20 official sets. Website version also takes MOC CSV uploads (Rebrickable dropped MOC API support entirely); the native in-app port (`parts_merger_screen.dart`) is official-sets-only, BrickLink XML export only, and lives in **Settings > Tools** (a deliberate placement choice, not Discover). BrickLink part/color ids come free from Rebrickable's own response fields.

**Parts Checker**: native port of `checker.html`, `GET /parts?set=`. Own small SQLite db keyed by set number; the Dashboard card and Set Detail's "Check for missing pieces" entry point share the same progress. Known gap: `qty` bakes in spare pieces (Parts Merger separates them out) — would need a shared `handleParts` fix to close for both surfaces.

**Social share cards** (Set/Collection/Den): `RepaintBoundary` → PNG → `share_plus`. Privacy default is ROI%-only, dollar amounts behind a toggle (top-gainers list is always ROI%-only, no toggle). `photo_backdrop.dart` is the shared photo-picker/compositor — cropping is freeform with a composition grid, letterboxed onto a cream background rather than force-cropped. Format toggle: Story (9:16) / Post (4:5, Instagram's real feed ratio). `BrikStaxMark` (`brand_mark.dart`) replaced the old emoji+text header everywhere; footer is standardized to `MadeWithBrikStax`. Per-screen photo-mode stickers: Set = `_SlabSticker` (PSA/StockX slab look, full stat parity with the no-photo card), Collection = `_GlassSticker` (frosted glass, full content parity), Den = `_DenMinimalSticker` (typography only). Set's Product Photo variant is a dark "trading card" style with a real QR code (`brikstax://set/<num>`) — one swipeable `PageView` across all 4 card variants.

**What's New quest system**: server-driven (`GET`/`POST /whats-new`, D1 table `whats_new_quests`), fetched once at launch, fails safe to nothing. Multi-entry-per-version — `id` is the real primary key, each entry shows its own intro popup exactly once. Four real task mechanisms exist (tap-to-claim, open-share-card, try-post-format, crop-own-photo); a 5th needs real app code wired in, not just a dropdown entry. Reward popup shows a live avatar preview. **Scheduling added 2026-08-26/27**: optional `active_at`/`ends_at` (`YYYY-MM-DD`, UTC) columns, `NULL` = no boundary (old behavior unchanged). Overlapping quests were never actually constrained — no `LIMIT`/uniqueness in the query. Two authoring tools: `tools/quest_builder.html` (offline, no live list) and `cloudflare-site/quest-admin.html` (live at `brikstax.pages.dev/quest-admin`, has a Scheduled Quests list — 🟢live/🕒upcoming/⚫ended — via an admin-only `GET /whats-new/all`). Two `[TEST]`-prefixed rows from feature verification are sitting in production data; no delete endpoint exists yet.

**Android build toolchain overrides** (`android/build.gradle.kts`): this project's Kotlin/AGP/Gradle versions are newer than several plugins' bundled defaults expect. Rule of thumb, proven twice over: `jvmTarget` is safe to override blanket across all subprojects; `languageVersion`/`apiVersion`/`compileSdk`/`compileOptions` must be scoped to the one plugin that needs it via `project(":x") { afterEvaluate { ... } }`, or it silently breaks a different plugin that needed its own (newer) values.

**Push notifications** (`push_service.dart`): real FCM, rebuilt 2026-08-26 into a **silent, automatic activation with no in-app UI** — `PushService.maybeAutoActivate()` runs on every launch, short-circuits immediately unless gated in. Gated by `DevMode.isOn` OR the `push_notifications` feature flag (off by default; flip via Worker env var, no app update needed). One real OS permission prompt on first gated-in launch, same shape as camera permission — never re-prompts after that, just quietly re-syncs. `topicAllUsers` (broadcast) / `topicDevAlerts` (dev-only, used by `lego-rewards-watcher`'s alerts) / `push_tokens` (future targeted sends). **iOS has no Firebase/APNs setup at all** — push silently no-ops there, confirmed non-blocking for shipping iOS without it. The Worker's `POST /push/send` is real (OAuth2-signed FCM v1), already used in production.

**Community likes/rewards**: `POST /community/like` toggles, `UNIQUE(post_id, user_id)` server-side. Owner earns 1 Brik/like, claimed via a pull (`POST /community/claim-rewards`) since Briks are local-only. **Open gap**: client hardcodes a 6h submit cooldown regardless of trust status; server actually allows 2h for trusted users — needs a design call before fixing. Feed photo ratio is 4:5 (Instagram-style).

**Deal of the Day**: purely `ORDER BY created_at DESC`. Deal History screen lists everything, not just the current single winner.

**Wishlist affiliate links**: Amazon has no compliant way to link a specific product (no ASIN available anywhere) — stays a search link until Amazon PA-API access clears. The real sales threshold for that is whatever Associates Central's own account page currently shows, **not a fixed number** — it moves, don't trust a cached figure. eBay's real direct-listing link (`GET /ebay/product`) needs `EBAY_CLIENT_ID`/`EBAY_CLIENT_SECRET`, not yet configured — falls soft to search until then.

**Home-screen widgets**: `HomeWidget.updateWidget()` needs `qualifiedAndroidName` explicitly — this project's `applicationId` (`com.brixstax.android`) differs from its Kotlin namespace (`com.brikstax.brikstax`), and without the qualified name every update silently threw `ClassNotFoundException`. Den widget's `RepaintBoundary` must be scoped to just the room, not the whole scrollable page. Random Set widget got the same fix but was never explicitly confirmed working on-device.

**Git**: private repo, `github.com/paulolsen1684-wq/BrikStax-app`, synced to a Mac for iOS builds via normal push/pull — expect real merge conflicts, not just noise.
